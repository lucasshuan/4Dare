## What was built
- `RoomChat()` (mounted by `RoomStage` as before): fixed root `[data-chat]` at `right-4 bottom-0 w-[340px] z-[35]`, `max-sm:inset-x-2 max-sm:w-auto`. It sets `--dock` on `<html>` (`56px`, phone `calc(60px + env(safe-area-inset-bottom))`, `0px` while the phone bar hides) and removes it on unmount.
- Tab: folded height 56 / 60 (phone: plus the safe area as padding, `box-content`). Open height is `round(0.62|0.66 × innerHeight)`. It opens in 0.5 s `gs.backOut(1.15)` and folds in 0.5 s `gs.p3InOut` (reduced motion: 0.2 s easeOut). The body stays mounted while it folds and unmounts when the fold ends, so a folded chat has no textbox.
- Head (`ChatHead`): a `<button aria-expanded aria-controls>`. Its label is "Open chat" / "Fold chat", plus ", N new messages" while unread. Desktop shows "Chat" and up to 3 unread senders' faces (24 px, −7 px overlap, 2 px sky ring, newest first). Phone shows `[av] Bia: text` ("You: …" for yours) or "Room chat", truncated. Then the count (24 px mono pill, invisible at 0, "99+") and the chevron (rotates 180°).
- Unread: `localStorage["4dare:chat-seen:<code>"]` (try/catch). The first load stores the newest id; opening the chat marks lines read as they come. Count = `countUnread`, faces = `unreadSenders`. Unread turns the head `bg-sky text-on-sky` and inverts the count. The CSS nudge (`animate-nudge motion-reduce:animate-none`) runs while unread. On each new unread line: hop `[0,−14,0,−5,0]` over 0.6 s (times warped for power1.out), count pop 0.3→1 in 0.45 s `backOut(3)`, a desktop bubble, and the live-region line. Reduced motion: no hop, nudge or pop.
- Bubbles (`ChatBubbles`, desktop only): `absolute bottom-full mb-3` (68 px above the folded tab), stacked with the newest at the bottom. In from y 16 / scale .8 (origin 85% 100%), 0.4 s `backOut(1.8)`; out to y 10 / scale .9, 0.3 s `p2In`. Each leaves 3.05 s after it arrived (server clock, so a stopped lab clock keeps it), or at once on open. `aria-hidden` (the live region speaks).
- List (`ChatList`): `role="log"` named "Messages", bottom-aligned, scrollable. It sticks to the bottom when it was there, and always after your own line.
  - Others: avatar 28 + name (truncated) + sunken bubble.
  - Yours: sky, right-aligned. Sending lines are faded. A failed line is a button that calls `retry(id)` and shows "Not sent. Tap to try again."
  - Emoji-only lines are 34 px with no bubble (`isEmojiOnly`).
  - System lines are wrapping pills in the viewer's language; players appear through `useWithNames`, live player first, snapshot as fallback.
  - Entrances play only for lines that arrive while the chat is open. Your line keeps still when its saved copy replaces the optimistic one.
- Compose (`ChatCompose`): 46 px pill and a 34 px send button, disabled while `cleanChatText` is null. Enter sends, the field clears and keeps the focus. `maxLength` 280. The draft survives folding. A fine pointer focuses the field on open; touch does not. Escape inside the chat folds it and focuses the head.
- Phone keyboard (1.11): while the chat field has focus, the root's `bottom` is lifted by `innerHeight − vv.height − vv.offsetTop`, and the sheet shrinks to fit `vv.height − 16`. While another editable field has focus (`focusin`/`focusout`), the folded bar is `display:none` and `--dock` is `0px`.
- Lab (`lab/scenarios/chat.ts`): it replays the lab room (re-entrant guard) to post the real `systemLines` at their `showAt`, then adds a scripted conversation in en/pt/ja, tied to match moments. It keeps only lines written by the lab moment and seeds React Query `["chat","STAGE"]` via `chatCache`. It also writes the seen key, so lines from the last 6 s are unread and those from the last 3.05 s pop. Examples: `?show=vote&at=3` (lit tab, 2 bubbles); `?show=lobby&at=-1` (quiet).

## Deviations from the plan
1. Bubble text is clamped to 4 lines (`line-clamp-4`). A 280-character bubble would otherwise cover half the screen; the full text is in the list.
2. A line that is unread and less than 3.05 s old when the chat first loads also pops a bubble, with no hop. A reload loses nothing, and this is how the lab shows bubbles from static fixtures.
3. The phone bar's hide while another field has focus applies only when the bar is folded. An open sheet already covers the page.
4. Escape uses a window keydown filtered by `insideChat`, not a handler on the root, because Biome's a11y rule forbids handlers on static elements.
5. `maxLength={280}` counts UTF-16 units, so emoji-heavy text stops a little early. It never goes over the server's 280 code points.
