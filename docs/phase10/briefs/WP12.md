#### Re-review fixes (wave 2)

Four low-severity defects found by the independent re-review, each fixed with a small change:

1. **`voteView` during a queued cast** (`src/game/view.ts`). When every card was confirmed before the theme show ended, the cast queued behind it (`reveal = cast`, `prev = theme`) and `view.vote` turned null while the theme show still played. `voteView` now also takes the theme show from `reveal.prev`, so the vote stays until the theme show's `until` (plan 1.4). Test: `view.test.ts` "stays while the theme show plays, even with the cast queued behind it" (present at `g.now` and `until − 1`, gone at `until`).
2. **Record started after it finished** (`src/game/engine.ts`, `finish`). `playStartedAt` is the cast's `until`; a match that ended during the cast (everyone but one leaves, or everyone gives up) kept it in the future, so `matchRecord` saved `startedAt > finishedAt`. When `finish` drops a running or queued show it now clamps `playStartedAt` to `min(playStartedAt, now)`. Only `record.ts` reads it after `finish`, and nothing changes it until the lobby resets it, so the record id (`code-startedAt`) stays stable across saves. Tests: `record.test.ts` "a match that ends during the cast starts when it ended, never after" (leave, give up, and a cast still queued behind the theme show), plus one assertion in the engine's mid-show test.
3. **Unanimous vote shown as a tie** (`src/features/vote/vote-screen.tsx`, interim until WP7). A vote that closed during the opening queued the theme show at `opening.until`, so `elapsed` was negative and `elapsed < spinMs` (0) showed "It's a tie! Spinning". `elapsed` is now clamped to ≥ 0, the spin needs `spinMs > 0`, and the screen keeps the voting stage (all votes in) until the theme show starts. A click on another card does nothing once the vote has a result. The screen also finds the theme show under a queued cast's `prev`, in line with fix 1.
4. **Queued shows in the simulation** (`src/game/simulation.test.ts`). Half the `START`s that open a vote are now followed at once by everyone's vote (during the opening), and a quarter of the steps advance only 0–500 ms. Both queued kinds happen (`theme<opening`, `cast<theme`), so `checkShow`'s `prev` checks run, and the test asserts both were seen. A new per-step check asserts the vote stays in every viewer's view while its theme show plays (fix 1). The new randomness produced the first tied places in the simulation (two discoveries in the same turn round: places 1, 1), which the old invariant (`1..n` without ties) rejected wrongly. It now checks podium places (`1, 1, 3`) and that tied places share a turn round. Runtime: about 6.3 s against 6.0 s for the old version on the same loaded machine.
